# 修复方案：建筑升级任务适配 2026 新版 UI

> 适用版本：coc_robot 当前 main 分支（b65ae1c）
> 基准环境：雷电模拟器 9，分辨率 800x600（本方案所有坐标均在此分辨率下实测）
> 实测方式：在模拟器中启动部落冲突，逐步截屏采集新版界面并测量坐标

---

## 补充（2026-10-27 二次实测）：新面板为统一列表 + 筛选器

进一步实测发现：
- 面板顶部 ⇔ 按钮不是页签切换，而是**筛选菜单**：可按资源（金币/圣水/黑油）、类型（**军队/防御/英雄/资源/陷阱/永久**）、排序（最高/最低花费）筛选。
- "建筑"和"英雄"已合并为同一个列表（标题即"建筑和英雄"），英雄通过类型筛选"英雄"过滤出来。
- 面板列表可滚动，条目含：缩略图、名称、等级徽章、剩余时间、费用、资源图标。

### 结论：推荐"修复 + 抽取共享面板驱动"路线，不推荐整体重写

理由：
1. **与 UI 无关的高价值逻辑应保留**：工人状态机（含哥布林活动、刷墙留工人等边界情况）、失败记录与重试间隔、数据库状态、异常恢复、企业微信通知、dataclass 配置自动生成 UI——重写等于把这些重新踩一遍坑。
2. **新面板"统一列表+筛选"恰好适合抽共享模块**：新建 `任务流程/新版升级面板.py` 面板驱动（打开/关闭/筛选/OCR 行/解析行信息/选中行/升级确认），建筑、英雄、研究、战宠四类任务都变薄，只写各自差异逻辑。这是"新开发"，但开发在正确的层上。
3. **风险可控**：修复路线可以逐任务干跑验证；重写则登录检测、世界跳转、打鱼链路等依赖这些任务状态数据的部分全要回归。
4. 待游戏内二次确认：研究（实验室）与战宠是否真已整合进此面板。若已整合则四类任务统一走面板驱动；未整合的部分（如战宠小屋在地图上的特殊流程）保留原逻辑仅校准坐标。

### 三次实测补充：四大升级入口全部整合确认（底栏图标实测）

面板底栏（y≈540~575）从左到右四个入口，坐标均已实测：

| 入口 | 图标 | 计数 | 坐标 | 点开内容 |
|------|------|------|------|---------|
| 建筑工人 | 工人头像 | 4/6 | (508, 555) | 主列表（建筑+英雄） |
| **研究** | 实验员+药水瓶 | 1/1 | **(593, 555)** | "军队计划"面板：兵种/法术升级列表，含建议升级/其他升级、等级、费用、剩余时间 |
| 英雄装备? | 铁砧+盾 | 无计数 | (668, 555) | 待确认 |
| **战宠** | 爪印金币 | 0/1 | **(756, 555)** | 战宠升级列表：战宠条目+费用+等级+队列总时长（如"4天18小时"） |

**结论确定**：建筑、英雄、研究（兵种/法术）、战宠四类升级在新版全部整合为同一套"右侧列表面板"交互模式，结构高度一致（条目=图标+名称+等级+费用+剩余时间）。共享面板驱动方案完全成立，四个任务可共用 90% 的面板操作代码。

### 目标架构

```
任务流程/新版升级面板.py     # 共享驱动：open/close/筛选(类型=英雄/军队等)/OCR行/解析/选中/确认
任务流程/建筑升级/           # 保留编排与状态机，UI 操作全部改走面板驱动
任务流程/战宠升级/           # 能走面板驱动的走驱动，地图特殊流程保留
任务流程/兵种或法术升级/     # 同上
配置/界面元素注册表.py       # 所有坐标/区域/模板/阈值集中管理
```

## 一、问题诊断

建筑升级任务链的识别手段有三类，全部受本次 UI 大改影响：

| 识别手段 | 依赖内容 | 受影响程度 |
|---------|---------|-----------|
| 固定坐标点击 | 硬编码像素坐标 | **全部失效**（布局重排） |
| OCR 区域识别 | 固定区域 + 锚点文字 | **区域失效，锚点尚存** |
| 模板图匹配 | img/ 下的小尺寸 BMP | **模板过期** |

### 实测确认的新旧差异（核心失效点）

| # | 失效点 | 旧版 | 新版（实测） | 涉及文件 |
|---|--------|------|------------|---------|
| 1 | 工人计数位置 | 顶部中间 (349,3,441,47) "0/6" | **右下角** "4/6"，主村庄约 (695~745, 480~505)；建筑面板底部栏约 (480~525, 498~522) | `更新工人状态.py` |
| 2 | 打开建筑面板 | 点击顶部 (353,13) | 点击**右下角"建造"锤子按钮** ≈ (728, 528) | `寻找建筑.py` |
| 3 | 面板 OCR 区域 | (219, 57, 595, 398)，左侧面板 | 面板移到**右侧**，约 (456, 7, 800, 473) | `寻找建筑.py` |
| 4 | OCR 坐标偏移量 | `+219 / +57`（解析坐标函数） | 应为 `+456 / +7` | `寻找建筑.py` |
| 5 | 面板滑动区域 | (399,116) 附近上下滑 | 面板在右侧，应在 ≈(620, 150~450) 内滑动 | `寻找建筑.py` |
| 6 | 关闭面板 | 点击 (353,13) | 点击面板右上角 **X** ≈ (735, 19) | `升级英雄.py` 等 |
| 7 | 升级锤子模板 | `建筑升级界面锤子.bmp`（20x21） | 界面重绘，模板必然失配，需重新截取 | `升级普通建筑.py` |
| 8 | 升级确认按钮 | 固定点击 (561,482) | 需在新对话框中重新测量 | `升级普通建筑.py` |
| 9 | 资源不足 HSV 检测 | 颜色 (250,135,124) | 新版行内资源图标/颜色变化，需重新校准 | `寻找建筑.py` |

### 好消息（可保留的部分）

- 新面板**仍保留"建议升级"和"其他升级"两个锚点文字**（实测 y≈113 和 y≈268），`提取建议升级建筑名称/提取建议升级建筑` 的 OCR 区间提取逻辑**整体可复用**，只需改区域和偏移。
- 新面板行结构为：缩略图 + 名称 + 等级徽章 + 剩余时间 + 费用+资源图标，OCR 文本仍然可解析。
- 新面板顶部新增"建筑/英雄"切换按钮（⇔，实测 ≈(495,19)），英雄升级入口更明确。
- 面板顶部两条绿色"建筑工人小屋 8天18小时"进度条可直接反映忙碌工人，可作为工人状态的**第二数据源**。
- `建筑升级任务`（`__init__.py` 编排层）、失败重试记录、`更新工人状态` 的状态机逻辑不受影响。

## 二、修复方案

### 阶段 0：建立"UI 元素注册表"（防止下次大改再返工）

新建 `配置/界面元素注册表.py`（或 JSON），把所有坐标、区域、模板、阈值集中管理：

```python
# 配置/界面元素注册表.py —— 800x600 分辨率实测值
新版UI = {
    "建造锤子按钮":   (728, 528),          # 主村庄右下角，打开建筑面板
    "面板关闭按钮":   (735, 19),           # 面板右上角 X
    "建筑英雄切换":   (495, 19),           # 面板顶部 ⇔
    "面板OCR区域":    (456, 7, 800, 473),
    "OCR偏移X":       456,
    "OCR偏移Y":       7,
    "工人计数_主村庄": (695, 480, 745, 505),
    "工人计数_面板内": (480, 498, 525, 522),
    "面板滑动起点":   (620, 420),
    "面板滑动终点":   (620, 160),
    "资源不足HSV":    (250, 135, 124),     # 待重新校准
}
```

所有任务代码从注册表取值。**本次修复顺便完成解耦，之后 UI 再改只需重新校准一份注册表。**

### 阶段 1：逐点修复（按任务链顺序）

**1.1 `更新工人状态.py`**
- OCR 区域改为注册表中 `工人计数_主村庄`；
- 新版数字为白字带黑描边，识别成功率应更高；保留 `O→0` 清洗逻辑；
- 增加备用方案：OCR 失败时读面板顶部绿色进度条数量（进度条条数 = 忙碌工人数）。

**1.2 `寻找建筑.py`**
- `打开建筑页面()`：改为点击 (728,528)（建造锤子按钮）；"建议升级"模式传 `划到底部=False` 的逻辑保留；
- `执行OCR识别` 区域改为 `(456, 7, 800, 473)`；
- `解析坐标()` 偏移量改为 `+456 / +7`，右下边界改为 `(800, 该行实际底边)`；
- `滑动到建筑栏底部()` / `滑动屏幕()`：起点改到面板内 (620, 420) 附近，纵向滑动；
- `检查升级条件()`：重新校准 HSV。方法：分别在资源充足/不足两状态下截取同一行区域，用项目里现成的 `是否包含指定颜色_HSV(..., 是否可视化=True)` 调试，确定新颜色与 `最少像素数` 阈值；
- "到顶了"判断：旧版依赖 OCR 到"升级中"，新版建议改为检测"建议升级"区为空或全部行显示剩余天数。

**1.3 `升级普通建筑.py`**
- 重新截取锤子模板：在升级确认对话框出现时截屏，裁剪新的"立即升级"锤子按钮，存为 `img/建筑升级界面锤子_新版.bmp`（可保留旧模板做兼容，用 `|` 拼接）；
- 确认按钮 (561,482) 在新对话框中重新测量后移入注册表。

**1.4 `升级英雄.py`**
- 关闭面板改点 X (735,19)；
- 英雄殿堂入口：先点 ⇔ (495,19) 切换到英雄页，再按新布局重截 `英雄殿堂界面_升级.bmp` / `英雄升级界面_确认.bmp` 模板。

### 阶段 2：模板重截工具

写一个 `工具包/模板截取工具.py`：框选截屏区域 → 自动保存 BMP + 打印坐标，替代"肉眼估坐标 + 手动裁剪"的老流程。每次 UI 改版后用它 10 分钟内完成全套模板更新。

### 阶段 3：验证流程（不消耗资源）

1. **干跑模式**：给 `升级普通建筑任务` 加 `只定位不点击` 开关，跑通"打开面板 → OCR → 选中建筑 → 定位锤子"全链路，日志输出每步识别结果；
2. 依次验证：工人状态识别 → 建议升级列表提取 → 指定建筑查找 → 锤子定位；
3. 全部通过后再放开真实升级，先跑一个小额目标（如 4 万圣水的精制台）做端到端确认；
4. 回归夜世界路径（`是否刷主世界=False` 分支的坐标 x=450 那套逻辑需要同样校准）。

### 阶段 4：健壮性加固（建议顺手做）

- **锚点相对定位**：以"建议升级/其他升级"文字的实测位置为基准，行坐标相对锚点计算，而不是全屏绝对坐标；
- **多分辨率适配**：注册表按键值存"相对比例"，运行时按 `wm size` 实际分辨率缩放；
- **失败截图留档**：定位失败时自动存截屏到 `数据库/失败截图/`，下次 UI 改版能快速定位失效点。
